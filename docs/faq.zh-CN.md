## 为什么我的结果是 Unverified？

Unverified 表示没有规则被证明不成立，但证据不足以说 Verified。命令行打印的摘要会列出适用的原因，CSV 核对页面会在 **这个结果是什么意思** 下逐条解释。常见原因：

- **没有声明来源文件是完整的一批**（`--source-complete`，页面上是 *来源文件是完整的一批*）。没有这项声明，就无法排除有属于这一批、却不在文件中的记录，所以即使文件里的每条记录都通过，这一批也永远不会是 Verified。
- **没有声明目标导出覆盖整个对象**（`--destination-complete`）。没有这项声明，找不到的记录不会被判为缺失，只找到一次的记录也不会被判为唯一。
- **文件与某项声明矛盾**：你声明的总数与文件行数不同，来源中有空的或重复的键，或者目标中有键为空的行。
- **有值无法比较**：值为空，或者规则读不了它，例如 `digits` 规则下不含数字的值，或者不符合日期格式的日期。

声明由你来作，而且只在你确知成立时才作。FlowAssert 无法检查它们。为了得到 Verified 而作出的声明，只会让结果出错，而不会让结果更可靠。要知道一项声明是否成立，可以把文件与它所来自的系统对比：例如，把文件的行数与系统显示的这一批总数对比。

## FlowAssert 能检查我的文件是否完整吗？

不能。CSV 文件无法显示导出时漏掉了什么：筛选条件、行数上限、只导出一页或导出中断，得到的文件看起来都是完整的。FlowAssert 没有连接你的系统，所以无法把文件和系统对比。正因如此，完整性是你作出的声明，连同它的来源一起写进报告。

总数能起一点作用。如果你传入系统显示的总数（`--source-count`、`--destination-count`，或页面上的两个总数），而它与文件行数不同，对应的完整性声明就会作废。总数相符并不能证明文件完整。

## 我的文件会离开电脑吗？

不会。

- **命令行** 只读取本地文件，不发任何网络请求。
- **浏览器核对** 在浏览器的 Web Worker 中读取文件。从选择文件到下载报告，它不发任何请求；在线演示的内容安全策略（CSP）禁止一切连接。你的选择和声明都不会被保存，除非你点了 **在这个浏览器中保存这份报告**，这会把那一份报告保存在这个浏览器配置文件中（见[已保存的报告](../README.zh-CN.md#已保存的报告和两次结果对比)）。
- **GitHub Action** 在你的工作流运行器上运行，不下载任何内容。除非设置 `show-records`，它的日志和任务摘要不显示任何键或值。
- **n8n 示例** 在你的 n8n 实例中运行；Code 节点不发任何请求。

CSV 核对页面和已保存的报告页面上的 **提交反馈** 链接，只有在你点击时才会在新标签页中打开 GitHub，而且不携带页面上的任何内容。

## 它和比对（diff）工具有什么不同？

比对工具回答“两个文件哪里不同”。FlowAssert 回答“这个结果有没有足够的证据”：

1. **区分不一致和证据不足。** 找不到的记录，只有在导出已声明覆盖整个对象时才算缺失；否则是 Unverified。
2. **前提必须明说。** 来源和导出是否完整由你声明，从不假定，并写进报告。
3. **重复不挑。** 两行目标数据带有同一个键时，不会随便选一行来比较。
4. **批次和记录分开。** 每条记录都通过，批次也可能是 Unverified。
5. **报告可以事后复查。** 报告保存文件摘要、时间和所用规则。

它还按你选择的规则比较，例如 `trim`、`casefold`、`digits` 或日期格式，从不自行推断规则。

## 能用在真实数据上吗？

能，在你自己的电脑上。命令行、浏览器核对、GitHub Action 和 n8n 示例都让文件留在原处；在线演示也是在你的浏览器中读取文件，不会上传。

需要注意的是在线演示上保存的报告。它的网站 `sun-sh902.github.io` 由这个 GitHub 账号的所有 GitHub Pages 网站共用，所以其中另一个网站可以读取你在那里保存的报告。报告包含记录的键和比较的值，除非它是用 `--redact-values` 写的。不希望被其他网站读取的报告，请在本地运行 UI（`cd ui && npm ci && npm run dev`），或者下载报告而不是保存在浏览器里。

FlowAssert 是只有一位维护者、没有经过安全审计的早期软件：请先阅读[已知问题](../README.zh-CN.md#已知问题)。Service 及其页面只处理 5 个审核过的合成样例，不用于真实数据。
