# 1.x 的兼容性

[English](compatibility.md) | 简体中文

本页说明：从 1.0.0 到 2.0.0 之前的每个 FlowAssert 版本里，哪些东西保持不变，哪些可能改变，一项功能怎样退役，以及读取报告的程序遇到不认识的报告时必须怎么做。

这是一个只有一位维护者的项目诚恳作出的承诺。它不是合同，也不附带任何支持义务。如果某个版本违反了它，那是缺陷，请报告。

## 1.x 涵盖什么

命令 `flowassert-verify`、网页界面的 CSV 核对、打包的 JavaScript 核对函数（`flowassert-check.js` 里的 `checkCsv`）和 GitHub Action，版本号在 1.0.0 及以上、2.0.0 以下的每个版本。

不包括本地 Service 和它的工作区页面：它们只处理 5 个合成样例，是原型。

## 哪些是稳定的

| 稳定的内容 | 在哪里定义 |
| --- | --- |
| **结论。** 同样的输入、选项和前提，得到同样的记录、规则结果、计数、批次状态和退出码 | [规范](spec/verification.zh-CN.md)第 4 到 9 节 |
| **报告格式。** 每个 `schema_version` 的每个成员、它的类型和含义。一个 `schema_version` 发布之后不再改动：不删除成员，不改名，不改含义 | [报告格式](report-format.zh-CN.md)、[JSON Schema](schema/) |
| **JSON 文本**：UTF-8，成员排序且 `schema_version` 在最前，缩进两个空格，ASCII 以外的字符转义 | 规范 R10.10 |
| **退出码**：0 已验证，1 不一致，3 未验证，2 拒绝，4 内部出错 | 规范第 13 节 |
| `flowassert-verify` 的**选项**：名称、取值、含义和默认值 | `flowassert-verify --help`、README |
| **默认值**：每个文件 209,715,200 字节和 1,000,000 行，摘要里 50 条记录行，明细 `problems`，编码 `utf-8`，范围 `source` | 规范第 3 节和第 11 节 |
| **拒绝信息的文字** | 规范第 12 节；连接器的见它的设计说明 |
| **打印的摘要**：各行、顺序和措辞 | 规范第 11 节 |
| **配置文件和映射文件**的成员 | 规范第 2 节 |
| **规则** `exact`、`trim`、`casefold`、`digits`、`date:FORMAT`，以及**范围** `source` 和 `exact` | 规范第 5 节和第 9 节 |
| **`checkCsv`**：参数的成员、结果的成员，以及全局名称 `FlowAssert` | README 的“在 JavaScript 里使用核对” |
| **GitHub Action** 的输入和输出 | `action.yml` |
| 这套行为的**评估器名称** `v2-current-state-1` | 报告的 `evaluator` 成员 |

“同样的结论”有两处限制，都写在规范第 15 节：`casefold`、`trim` 和空键所说的空白，跟随运行核对的 Python 的 Unicode 版本；`date:FORMAT` 跟随这个 Python 的 `strptime`。如果值里用到不同 Python 版本处理不一致的字符或日期写法，它在两个版本上的比较结果可能不同。核对样例里没有这样的值。

## 哪些可能改变

任何 1.x 版本都可能改变以下内容，只在更新日志里说明：

- **HTML 报告的标记和外观。** 它是给人看的。它始终显示 JSON 报告里的结果，转义每个值，不含脚本，不加载任何东西；但它的字节并不稳定。
- 网页界面：布局、界面文字、中文文字，以及显示在结果旁边的所有内容（“这个结果是什么意思”、文件概况、核对前的提示、结果浏览器、字符高亮、拒绝提示）。这些都不在报告里。
- 参数解析器的用法错误文字，以及拒绝信息里来自操作系统的部分。
- `flowassert_offline` 下的 Python 模块和 `ui/src/offline` 下的 TypeScript 模块：它们不是编程接口。命令和 `checkCsv` 才是。
- 速度和内存占用。
- n8n 示例工作流、合成场景和示例文件。
- 本地 Service、它的 API 和页面。

## 怎样新增

1.x 版本可以新增：

- **报告成员**：现有成员都不变时，不换 `schema_version`。新成员会写进[报告格式](report-format.zh-CN.md)、Schema 和更新日志；读取方在认识它之前忽略它；
- **`schema_version`**：一种新报告让现有成员有了别的含义时，就用新版本，比如版本 2 用于 Google Sheets 来源，版本 3 用于 HubSpot 目标。原有种类的报告保持原来的版本和字节；
- **选项**：不使用它时，现有的每条命令都和以前一样；
- **拒绝**：针对新选项才可能出现的输入，或者针对以前被错误接受、可能在证据不足时给出结果的输入。后一种是纠错，更新日志会写明；
- 前提里 **`origin` 的取值**：有了新的声明途径时。

1.x 里不会新增规则、范围、记录状态或规则状态：读取方依赖它们的完整集合。

## 弃用

[哪些是稳定的](#哪些是稳定的)里列出的内容，在 1.x 里都不会删除。

如果某个选项、默认值或报告成员要在 2.0 退役：

1. 先由一个 1.x 版本在更新日志、README 或[报告格式](report-format.zh-CN.md)里把它标为**已弃用**；选项还会在 `--help` 里标明。
2. 在之后的每个 1.x 版本里，它照常工作。不打印任何警告，所以现有命令的输出不变。
3. 2.0 至少在这项通知发出**六个月**之后、并且至少隔**两个版本**才发布。
4. 报告成员只随新的 `schema_version` 退役。2.x 的读取方仍然读取 1.x 的各个版本，否则会明确说明不读。

## 读取方必须做什么

读取 FlowAssert 报告的程序：

- **必须先读 `schema_version`**；版本不认识，或者没有版本时，**必须**拒绝这份报告，并说明读到的是哪个版本、自己能读哪些版本。**不得**把报告当作自己认识的最接近的版本来读：出现新版本，正是因为某个成员有了别的含义。
- 在认识的版本里，**必须忽略不认识的成员**，**不得**因此失败。
- **必须把不认识的前提**当作 FlowAssert 没有验证过的声明，把不认识的 `origin` 当作要原样显示的文字。
- **不得通过读取拒绝信息或原因的文字来判断结果。** 结果是 `cohort_state`、每条记录的 `state` 和每条规则的 `status`。
- **不得把报告当作经过认证的。** 报告里的摘要值说明读到的是哪些字节，不说明报告是谁写的。

网页界面的已保存报告页面遵守这些规则（[对比两份报告](report-comparison.md)，仅英文）。

## 什么情况需要 2.0

删除或重命名选项；修改默认值或退出码；修改拒绝信息或摘要行的措辞；增加或删除规则、范围或状态；对同样的输入改变结论。这些都没有计划。
