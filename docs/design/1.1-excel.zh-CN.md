## 新增了什么，什么不能变

大多数业务导出是 `.xlsx` 工作簿。从 1.1.0 起，核对的每一侧都可以是工作簿里的一个工作表，直接读取，保证与 CSV 文件相同：严格地只读一次，从不猜测，宁可拒绝也不读一部分，并在报告里连同摘要一起记录。

已有的东西都不变。不用新选项时，每个命令、拒绝信息、摘要和报告都与 1.0.0 逐字节相同。只有用户明确说明时，文件才按工作簿读取：没有 `--source-format xlsx` 而把 `.xlsx` 文件交给 `--source`，仍按 CSV 读取，并像 1.0.0 那样被拒绝。FlowAssert 从不根据文件名选择格式。

## 选项

| 选项 | 取值 | 含义 |
| --- | --- | --- |
| `--source-format FORMAT` | `csv`（默认）或 `xlsx` | `--source` 怎样读取 |
| `--destination-format FORMAT` | `csv`（默认）或 `xlsx` | `--destination` 怎样读取 |
| `--source-worksheet NAME` | 工作表名称，与工作簿里的写法完全一致 | 与 `--source-format xlsx` 一起用：要读的工作表 |
| `--destination-worksheet NAME` | 同上 | 与 `--destination-format xlsx` 一起用 |

下面的组合会被拒绝，都在读取任何文件之前，按这个顺序排在编码之后（规范 R12.3）：

- `--source-format must be one of: csv, xlsx`（以及 `--destination-format …`）；
- 与 `--source-sheet` 一起用时 `--source-format does not apply to a sheet source`；与 `--destination-hubspot` 一起用时 `--destination-format does not apply to a HubSpot destination`；
- `--source-worksheet needs --source-format xlsx`（以及 `--destination-worksheet …`）；
- 与 `--source-format xlsx` 一起用时 `--source-encoding does not apply to a workbook`（以及 `--destination-encoding …`）：工作簿的各部分都是 UTF-8 的 XML，FlowAssert 不读其他编码。

`--max-bytes` 和 `--max-rows` 的名称和默认值不变，但它们限制的是解压后实际读取的内容，不只是文件大小（[拒绝和上限](#拒绝和上限)）。

浏览器根据用户选择的文件判断格式（工作簿以开头的字节 `PK\x03\x04` 和以 `.xlsx` 结尾的名称识别），并在核对前显示出来；打包的核对函数在每个文件上接受 `format: "xlsx"` 和 `worksheet`；Action 接受 `source-format`、`source-worksheet`、`destination-format` 和 `destination-worksheet` 这几个输入。

## 选哪个工作表

工作簿在 `xl/workbook.xml` 里列出它的工作表（`sheets/sheet`，带 `name`、`sheetId`、`state` 和 `r:id`）**[doc]**。FlowAssert 按顺序读每个 `sheet` 元素，通过 `xl/_rels/workbook.xml.rels` 解析 `r:id`。

- **给了名称**（`--source-worksheet`）：取 `name` 与它完全相同（逐个码点比较）的那个。没有匹配的名称会被拒绝，并列出工作簿里的名称。名称指向图表工作表、对话框工作表或宏工作表（关系类型不是 `…/relationships/worksheet`）时也会被拒绝：它们没有单元格。
- **没给名称**：只有工作簿恰好只有一个工作表、且它是普通工作表时才读取。有两个或更多工作表时（包括隐藏的），FlowAssert 不替用户选择：隐藏的工作表里可能正是用户要的行，第一个可见的未必是。拒绝信息会列出每个工作表。
- **隐藏**或**深度隐藏**的工作表，只要指名就会读取。报告会记录它的状态。

## 从文件到工作表

`.xlsx` 工作簿是一个装着 XML 部分的 ZIP 压缩包（Office Open XML，ECMA-376 第 2 部分，开放打包约定）**[doc]**。FlowAssert 用自己的 ZIP 读取器读取，Python 和 TypeScript 里相同：

1. **文件开头的字节。** `D0 CF 11 E0 A1 B1 1A E1` 是 OLE 复合文件：旧的 `.xls` 工作簿和设置了密码的 `.xlsx` 工作簿都是这样存储的（**[unconfirmed]**：读过的来源都没有这样说；FlowAssert 对所有 OLE 复合文件一律拒绝，所以没有任何东西依赖这一点），FlowAssert 两种都不读。其他结尾没有 ZIP 中央目录结束记录的文件都不是工作簿。
2. **中央目录**，从最后 65,557 个字节里的结束记录找到。它是依据：每个条目的名称、方法、大小、CRC-32 和偏移都从这里取。需要 ZIP64 的压缩包（有 ZIP64 结束记录）会被拒绝；条目上的 ZIP64 扩展字段会读取。最多 10,000 个条目。两个条目名称在忽略 ASCII 大小写后相同时拒绝，因为包里的部分名称就是这样比较的 **[doc]**。
3. **要读的每个部分**按名称查找，本地文件头要与中央目录一致（名称、方法），数据以流的方式解压：只接受方法 0（不压缩）和 8（deflate）。解压出的字节边到达边计数，不得超过剩余的字节预算；结束时必须等于目录记录的大小和 CRC-32。带加密标志的条目会被拒绝。
4. **各部分**，按这个顺序：`[Content_Types].xml`；`_rels/.rels`，它的 `…/officeDocument` 关系指出工作簿部分；工作簿部分，它的内容类型必须是 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet.main+xml`（启用宏的工作簿、二进制工作簿、模板和严格 Open XML 工作簿的类型或关系名称不同，都会被拒绝）；工作簿的关系；有的话再读 `styles.xml` 和 `sharedStrings.xml`；最后读那一个工作表。不打开其他部分。FlowAssert 读取的任何部分，关系上有 `TargetMode="External"` 都会被拒绝。

命令行只打开文件一次，用定位读取。文件的 SHA-256 在读各部分之前，单独遍历一遍所有字节算出；各部分读完后，再把文件大小和修改时间与开始时比较，文件变了就拒绝。在浏览器里，选定的文件不会变化，各部分用 `Blob.slice` 读取，由平台的 `DecompressionStream("deflate-raw")` 解压。从不请求任何部分：页面不发出请求。

## FlowAssert 读取的 XML

各部分都是 XML 1.0。FlowAssert 不用通用的 XML 解析器：Python 和浏览器的解析器接受的内容不同，Web Worker 里也没有。它只有一个分词器，写了两遍，只读 XML 的一个子集（Excel 和常见写入程序写出的部分都在其中），子集之外的一律拒绝。两边相同：

- **编码**：UTF-8，可以有字节顺序标记。XML 声明写了别的编码、有 UTF-16 字节顺序标记、或者有不是 UTF-8 的字节序列，都会被拒绝（`not UTF-8`）。
- 任何位置出现 **`DOCTYPE`** 都会被拒绝，所以不能声明实体，也不会展开实体。
- **引用**：五个预定义实体（`&lt;` `&gt;` `&amp;` `&quot;` `&apos;`）和指向 XML 允许的字符的字符引用（`&#N;`、`&#xH;`）。其他的 `&` 都不是格式正确的 XML。
- **标记**：元素、属性、字符数据、`CDATA` 段、注释和处理指令（XML 声明也是一种）。名称按 XML 的名称字符检查；结束标签必须与开始标签对应；一个属性不能出现两次；根元素之外的文本只能是空白。
- **命名空间**会解析。元素和属性按命名空间和本地名称识别，所以 SpreadsheetML 命名空间里的 `<x:c>` 也是单元格；没有绑定的前缀不是格式正确的 XML。
- **规范化**，按 XML 1.0 的要求：文本和属性里的 CR LF 和单独的 CR 变成 LF，然后属性值里的制表符、LF 和 CR 变成空格。字符引用不做规范化。
- **上限**：一个标签（从 `<` 到 `>`）最多 65,536 个字符，元素嵌套最多 64 层。

子集之外的部分一律按 `not well-formed XML` 拒绝，不给更多细节，所以两个实现不可能对同一个文件给出两种不同的信息。不论平台解压时切出的块有多大，每个问题都按它在解压后文本中的位置先后处理：不是 UTF-8 的字节或 XML 禁止的字符，只在它之前的文本都读完以后才拒绝。唯一的例外是 deflate 数据流在中途损坏：Python 的 zlib 不会给出出错那一块里的任何文本，浏览器可能给出一部分；两者都会拒绝（规范第 15 节）。

## 从工作表到行

工作表的单元格是 `sheetData/row` 里的 `c` 元素 **[doc]**。FlowAssert 按文档顺序读取：

- **单元格引用。** `row` 有可选的 `r`，即行号；`c` 有可选的 `r`，例如 `B7` **[doc]**。没有时，行就是上一行的下一行，单元格就是这一行里上一个单元格的下一个。引用超出 `A1` 到 `XFD1048576`，或者不在上一个之后（行和单元格都必须递增），都会被拒绝。
- **表头是第 1 行，从 A 列开始。** 它最后一个非空单元格决定宽度；中间的空单元格是名为空字符串的列，就像 CSV 文件里的 `,name`。第 1 行为空会被拒绝，并说明原因：FlowAssert 从第 1 行读取列名。
- **数据行**是之后至少有一个非空单元格的行。没有非空单元格的行，不论是没有 `row` 元素、没有单元格还是只有空单元格，都不算记录：跳过，不计数，就像 CSV 文件里的空行。
- 数据行里**省略的单元格**是空的，就像 Google 表格范围里一行末尾省略的单元格。
- **表头最后一列右边的非空单元格**会被拒绝，就像 CSV 文件里比表头宽的行。
- **合并单元格。** 合并区域的值存在第一个单元格里，其余单元格存的是空，尽管电子表格把值显示在整个区域上 **[doc]**。FlowAssert 读的是存储的内容，所以只有第一个单元格有值；它还会统计合并区域（`mergeCells/mergeCell`），写进报告和摘要。
- **隐藏的行和列**（`row/@hidden`、`cols/col/@hidden`）和其他行列一样读取，包括被筛选隐藏的行。FlowAssert 会统计它们：用户可能以为筛选后的导出只有看得见的那些行。
- **工作表的每个单元格**都有下文规定的文本，否则拒绝这个文件，包括不参与比较的列的单元格：规范形式、它的摘要和待补发清单（[设计说明](1.1-exports.md)，中文版随第 3 项任务完成）都包含每一列。

## 单元格的文本

类型是单元格的 `t` 属性，没有时是 `n` **[doc]**。文本在 Python 和 TypeScript 里相同，与地区设置、时区和程序都无关。

| `t` | 存的是什么 **[doc]** | FlowAssert 读到的文本 |
| --- | --- | --- |
| `s` | 共享字符串表里的序号 | 那一项的文本：它的 `t`，或者各个 `r` 片段的 `t` 连起来；不含注音片段（`rPh`）。序号不是范围内的整数时拒绝 |
| `inlineStr` | `is` 元素里的字符串 | 同上，从 `is` 取 |
| `str` | 公式的字符串结果，在 `v` 里 | 原样取 `v` |
| `b` | `v` 里的 `0` 或 `1` | `FALSE` 或 `TRUE`，与电子表格自己导出 CSV 时的写法相同 **[doc]**。其他值拒绝 |
| `n` | `v` 里的数字，`xsd:double` 的写法 | 取决于数字格式：[数字格式](#数字格式)。没有 `v` 也没有公式：空单元格 |
| `d` | `v` 里的 ISO 8601 日期或时间 | 原样取 `v`，前提是它是 `YYYY-MM-DD`，后面可以跟 `THH:MM`、`:SS`、小数部分和 `Z` 或 `±HH:MM`；否则拒绝 |
| `e` | 错误值，例如 `#N/A` 或 `#DIV/0!` | 拒绝，并指出单元格和错误值。错误值没有可以如实比较的文本 |

各种类型的文本都遵守：

- **转义。** `_xHHHH_`（四个十六进制数字）表示那个字符，`_x005F_` 表示下划线，用于写入程序无法直接放进 XML 的文本（**[unconfirmed]**，见[来源](#来源)）。FlowAssert 会解开它们，所以 Excel 存成 `_x000D_` 的换行读作回车符。解出半个代理对的转义会被拒绝。
- **空白**原样保留：不去首尾空格，与 CSV 文件相同。XML 自己的规范化照样生效：部分里写成 CR LF 的换行读作 LF；写成 `_x000D_` 或 `&#13;` 的仍是 CR。
- **公式**（`f`）从不计算。读它保存的结果 `v`，按单元格类型解释：即文件最后保存时的值。有公式却没有 `v` 时，没有 FlowAssert 能读的值，会被拒绝。
- **超过 131,072 个字符的单元格**会被拒绝，与 CSV 字段相同。

## 数字格式

数字单元格的样式（`s`，指向 `styles.xml` 里 `cellXfs` 的序号，没有时是 0）指定一个数字格式（`numFmtId`）**[doc]**。格式只决定数字的文本怎样写，从不决定单元格是否读取：

1. **格式代码。** 先看 `numFmts/numFmt` 里的自定义代码；没有时，用 ECMA-376 为所有语言列出的内置编号对应的代码 **[doc]**：0 `General`、1 `0`、2 `0.00`、3 `#,##0`、4 `#,##0.00`、9 `0%`、10 `0.00%`、11 `0.00E+00`、12 `# ?/?`、13 `# ??/??`、14 `mm-dd-yy`、15 `d-mmm-yy`、16 `d-mmm`、17 `mmm-yy`、18 `h:mm AM/PM`、19 `h:mm:ss AM/PM`、20 `h:mm`、21 `h:mm:ss`、22 `m/d/yy h:mm`、37 `#,##0 ;(#,##0)`、38 `#,##0 ;[Red](#,##0)`、39 `#,##0.00;(#,##0.00)`、40 `#,##0.00;[Red](#,##0.00)`、45 `mm:ss`、46 `[h]:mm:ss`、47 `mmss.0`、48 `##0.0E+0`、49 `@`。其他编号的含义取决于写这个文件的程序的语言 **[doc]**，工作簿没有定义而数字单元格用了它时拒绝。
2. **节。** 一个代码最多有四节，用引号外的 `;` 分开：第一节用于正数，第二节用于负数，第三节用于零 **[doc]**。使用适用于这个值的那一节：负数且有第二节时用第二节，零且有第三节时用第三节，其他情况用第一节。
3. **清理。** 从这一节里去掉：双引号里的文字；`\`、`_` 或 `*` 后面的那个字符；任何大小写的单词 `General`；除表示经过时间的（任何大小写的 `[h]`、`[hh]`、`[m]`、`[mm]`、`[s]`、`[ss]`）以外的所有方括号内容，例如 `[Red]`、`[$-409]` 或 `[>=100]`。
4. **类别。** 清理后的节转成小写：含有经过时间的标记时是**时长**；否则按字母判断日期和时间：`y`、`d` 和表示月份的 `m` 是日期部分；`h`、`s`、`am/pm`、`a/p` 和表示分钟的 `m` 是时间部分。一串 `m` 前面最近的日期或时间字母（跳过其他字符）是 `h`，或者后面最近的是 `s` 时，表示分钟；否则表示月份。`e` 后面跟 `+` 或 `-` 时是数字的指数，否则是日期部分（纪年）。没有日期和时间部分的节，含 `%` 时是**百分比**，否则是**数字**。节里剩下其他任何字母（`b`、`g`、`n`……）时，FlowAssert 不读这个格式，拒绝这个单元格。

| 类别 | 文本 |
| --- | --- |
| 数字、百分比、时长 | 数字本身，[写法见下](#数字的文本)。百分比是存储的小数：显示 `12.5%` 的单元格读作 `0.125`。时长是存储的天数：`36:00:00` 读作 `1.5` |
| 日期、时间或两者都有 | [日期和时间](#日期和时间) |

### 数字的文本

`v` 必须匹配 `-?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?`；其他写法（`+` 号、`INF`、`NaN`、空白）都会被拒绝。它被读成最接近的 IEEE 754 双精度数，再按 ECMAScript 的 `Number::toString` 写出这个数（ECMA-262 的 `Number::toString(x)`，基数 10）**[doc]**：读回来仍是同一个数的最短数字；规范里的十进制指数 n 在 -5 到 21 之间时（也就是从 `0.000001` 到 `100000000000000000000`）用普通写法，超出时写成 `1e+21` 或 `1.5e-7`；`-0` 写成 `0`。不是有限数的值会被拒绝。所以 `45678`、`0.1`、`13800138000` 和 `12.5` 都按原样读出，存储的 `1.1000000000000001` 读作 `1.1`。

TypeScript 用 `String(x)` 写。Python 从 `repr(x)` 写：它的数字就是同样的最短数字 **[doc]**，再按同一条规则放置小数点；一项测试用随机的双精度数和这条规则的每个边界比较两者。

## 日期和时间

带日期或时间格式的数字单元格存的是天数序列号 **[doc]**。不论表格显示成什么格式，FlowAssert 都按工作簿的日期系统，把它代表的日期写成 ISO 8601：

- **日期系统**：`workbook.xml` 的 `workbookPr` 里 `date1904` 为真时是 1904 系统，否则是 1900 系统 **[doc]**。1900 系统里序列号 1 是 1900-01-01，并且把 1900 年当作闰年，所以序列号 60 是并不存在的 1900 年 2 月 29 日，序列号 61 是 1900-03-01；上限是序列号 2,958,465，即 9999-12-31。1904 系统里序列号 0 是 1904-01-01，上限是 2,957,003 **[doc]**。
- **毫秒**：`floor(x × 86,400,000 + 0.5)`，用 IEEE 754 双精度运算，两种语言里相同；再分成整天数和余下的毫秒。
- **文本**：时间类别且整天数为 0 时写成 `HH:MM:SS`；日期类别且没有余下的毫秒时写成 `YYYY-MM-DD`；其他都写成 `YYYY-MM-DDTHH:MM:SS`。毫秒不是整秒时，各自再加 `.mmm`。没有时区：工作簿不存时区。
- **拒绝**：负的序列号；1900 系统里带日期部分的序列号 60 和 0；超过日期系统上限的序列号。拒绝时指出单元格和序列号。

所以格式为 `yyyy/m/d`、`mm-dd-yy` 或 `d-mmm-yy` 的 `45973` 都读作 `2025-11-12`，格式为 `m/d/yy h:mm` 的 `45973.5` 读作 `2025-11-12T12:00:00`。

## 读存储的值，不读显示的样子

电子表格按格式显示单元格，FlowAssert 读文件里存储的值。两者在这些情况下不同：带格式的数字（`1,234.50` 读作 `1234.5`；格式为 `00000` 的 `00123` 读作 `123`）、百分比、日期、时长、逻辑值，以及公式（读的是最后保存的值）。如果目标里存的是显示出来的文字，用户需要知道这一点。所以：

- 报告按形式统计数据单元格（下面的 `cells`）；
- 摘要对每个从工作簿读取的一侧说明：单元格按存储的值读取，以及有多少个不是普通文本（[打印的摘要](#打印的摘要)）；
- 浏览器在核对前的文件概况里，用文字列出同样的计数。

## 规范形式和两个摘要

`inputs.source_sha256`（或 `destination_sha256`）是规范形式 `flowassert-xlsx-csv-1` 的 SHA-256，它的文本与 `flowassert-sheet-csv-1` 相同（[报告格式](../report-format.zh-CN.md)）：UTF-8，没有字节顺序标记；第 1 行是表头，之后每个数据行用空字符串补齐到表头的宽度，每行后面一个换行符；单元格含有 `,`、`"`、回车或换行，或者是所在行唯一且为空的单元格时，写在双引号里，其中的每个 `"` 写两次。`flowassert-verify --source` 读这段文本，得到的正是工作表给出的那些行。`inputs.source_workbook.file_sha256` 是文件字节的 SHA-256。

所以两个摘要回答两个问题。文件的摘要说明读的是哪个文件；规范形式的摘要说明读到的是哪些行，两个存着同样单元格的工作簿，不论由哪个程序写出，这个摘要都相同。“内容完全相同”比较的是规范形式的摘要：存着同样行的工作簿和 CSV 文件算内容完全相同，没有 `--allow-identical-content` 时会被拒绝，就像两个这样的 CSV 文件一样。

## 报告

有一侧从工作簿读取的报告，**`schema_version` 是 4**，因为这时 `inputs.source_sha256` 和 `inputs.destination_sha256` 描述的是规范形式而不是文件，`source_rows_observed` 和各计数的 `observed` 描述的是工作表的行。已有种类的报告保持原来的版本和字节。版本 4 含有版本 1 的全部成员，除从工作簿读取的一侧外含义相同；`inputs.source_sheet` 和 `inputs.destination_hubspot` 出现时，保持版本 2 和 3 中的含义。

每个从工作簿读取的一侧都有 `inputs.source_workbook` 或 `inputs.destination_workbook`：

| 成员 | 含义 |
| --- | --- |
| `format` | 总是 `xlsx` |
| `worksheet` | 工作表名称 |
| `worksheet_state` | `visible`、`hidden` 或 `veryHidden` |
| `sheets` | 工作簿列出的工作表数 |
| `date_system` | `1900` 或 `1904` |
| `file_sha256` | 文件字节的 SHA-256 |
| `file_bytes` | 文件大小 |
| `inflated_bytes` | 所读各部分解压出的字节数 |
| `columns` | 表头的宽度 |
| `rows` | 数据行数；对来源而言等于 `source_rows_observed` |
| `cells` | 按读取方式分类的数据单元格：`text`、`number`、`percentage`、`date_time`、`duration`、`boolean`，各为一个计数；以及 `formula`：其中值是公式保存的结果的单元格 |

| `merged_ranges` | 工作表里的合并区域 |
| `values` | 总是 `stored`：单元格按存储的值读取，不按显示的样子 |
| `canonical_form` | 总是 `flowassert-xlsx-csv-1` |

## 打印的摘要

对每个从工作簿读取的一侧，在计数行和连接器的行之后（规范第 11 节），按先来源后目标的顺序：

```text
Source read from worksheet 'Forms' of an .xlsx workbook: cells as stored, not as displayed.
  Read as stored, where a spreadsheet may display them otherwise: 14 numbers, 2 percentages as fractions, 10 dates or times in ISO 8601, 1 duration in days, 2 booleans as TRUE or FALSE, 2 formula results as last saved.
  Hidden: 2 rows, 1 column, read like any other. Merged ranges: 1, read as stored: only the first cell of each holds the value.
```

有数据单元格不是文本或是公式的结果时出现第二行，按上面的顺序列出不为零的计数；有隐藏的数据行或表头列，或有合并区域时出现第三行，列出其中不为零的部分。计数为一时用单数（`1 number`、`1 percentage as a fraction`、`1 row`）。这些行只为工作簿新增：已有摘要的任何一行都不变，工作簿一侧的计数行也保持原来的措辞（“file has N rows”）。

## 流式读取和内存

| 保留的内容 | 原因 | 上限 |
| --- | --- | --- |
| 中央目录 | 用来找到各部分 | 10,000 个条目 |
| 共享字符串表，作为字符串 | 单元格按序号引用其中的项，顺序任意 | 它解压后的大小，在 `--max-bytes` 以内 |
| 数字格式和单元格样式 | 很小 | 在 `--max-bytes` 以内 |
| 一行单元格 | 建好后交给核对 | 表头的宽度 |
| 一块压缩数据和一块解压后的文本 | 每次读 64 KiB | 固定 |

工作表从不整个放进内存：解压后的文本边到达边分词，每一行结束时就交给核对，与 CSV 的行完全一样。除了核对本身保留的内容（来源中参与比较的列，与 CSV 相同），内存只随共享字符串表增长。浏览器里共享字符串存成一个字符串加一个偏移数组，所以一百万项不需要一百万个对象。

## 为什么工作表和 CSV 文件得到同样的结果

核对消费的是行：一个表头，以及每个数据行的值。工作表给出的文本行与 CSV 文件给出的完全一样，此后在两个实现里都由同一段代码判断。所以同样的行得到同样的记录、规则结果、计数、批次状态和退出码（规范 R14.1 已经对连接器这样规定）。

“同样的行”指 FlowAssert 读到的文本，不是电子表格显示的样子：日期按 ISO 形式读取，而从同一个工作表导出的 CSV 文件里可能是 `11/12/2025`。有两处差异是有意的：工作表里没有非空单元格的行会被跳过，而 CSV 里全是空字段的行（`,,`）算作一行；工作表里较短的行会被补齐，而 CSV 里较短的行会被拒绝。一项测试把工作表能表达的每个核对样例（UTF-8，没有全是空字段的行，没有较短的行）两种方式各跑一遍，要求记录、规则结果、计数、批次状态和退出码相同。

## 测量

在构建用的机器上测得（Apple 芯片，macOS），使用 1.0 流式读取说明里的大文件基准。

每个工作簿：一个工作表，1,000,000 个数据行、三列（共享字符串的键、共享字符串、带格式的数字），压缩后 22 MB，解压后约 170 MB，共 2,000,003 个共享字符串。

| 运行 | 行数 | 得出结果的时间 | 内存 |
| --- | --- | --- | --- |
| 命令行，两个工作簿（Python 3.15） | 各 1,000,000 | 19.4 秒 | 常驻内存最多 568 MB |
| 命令行，同样的行放在两个 CSV 文件里 | 各 1,000,000 | 3.4 秒 | 常驻内存最多 400 MB |
| 只有 TypeScript 读取器，一个工作簿（Node 26） | 1,000,000 | 2.8 秒 | 读完后堆 128 MiB |

命令行读工作簿比读 CSV 慢：Python 用自己的、用 Python 写的分词器读 XML，而 CPython 的 CSV 读取器是用 C 写的。一条严格的快速路径用一个模式各取下整行和整个共享字符串，并由 `test_the_fast_path_and_the_tokenizer_read_rows_the_same_way` 保证它与分词器的结果相同；它让时间减半。比 CSV 多出来的内存是共享字符串表，读目标时一直保留。
