## 每个部分都遵守的规则

1. **辅助信息永远不是结论。** 概况、提示、高亮和筛选都是从文件或报告中读出的。它们都不改变文件、选择、声明或报告，也都不是结论。每一项都标明它是什么。核对的结果是唯一的结论。
2. **一个数字只有一条计算路径。** 核对前显示的行数来自 `readCsv`，也就是核对读取文件所用的函数。声明的总数用 `sameCount` 与它比较，这是评估器使用的函数。一项测试对每个核对样例和每个场景，比较概况的计数与报告的计数。
3. **什么都不离开浏览器。** 一切都在页面和它的两个 Worker 中运行。从选择文件到下载报告之间不发出任何请求，在线演示的内容安全策略仍然禁止一切连接。
4. **什么都不被记住。** 概况只在文件被选中期间存在。地址栏中的结果浏览状态只包含数字和固定的词，从不包含文件中的值、键或列名。
5. **每个状态都经过设计**：英文和中文，浅色和深色，桌面宽度和手机宽度，只用键盘也能操作。

## 文件概况

文件可以通过“选择文件”按钮选择，也可以拖放到它的面板上。整个面板都是放置区域；拖着文件经过时，面板显示品牌色虚线轮廓和“把文件放在这里”。一次拖放多个文件时一个也不接收，并显示“请只拖放一个文件：这次没有接收任何文件。”。按钮仍然是键盘操作的途径。

文件一被选中，概况 Worker 就做两件事：

1. **表头**从文件开头读取，与以前一样，所以列的下拉清单立即可用。
2. **概况**以流的方式读完整个文件，使用 `readCsv`，选中每一列。它给出：

| 显示 | 来自 |
| --- | --- |
| 数据行 | `readCsv` 返回的计数：空行不是行 |
| 列，以及每列的空单元格数 | 等于空字符串的单元格 |
| 编码 | 所选的编码，从不猜测 |
| 字节顺序标记 | 文件开头的字节：UTF-8 为 `EF BB BF`；UTF-16 为 `FF FE` 或 `FE FF`，它说明字节顺序；GB18030 为 `84 31 95 33`，与 Python 读取时一样，这个标记仍然是第一列列名的一部分 |
| 换行符 | 读取器遇到的换行符：LF、CRLF、CR，混用时给出各自的数量。引号值内部的换行也计入，因为它在文件中 |
| 大小 | `File.size`，以字节和取整后的单位显示 |

概况标为“文件概况 · 在核对前从文件读取”。两个 Worker 把辅助信息与核对分开：概况 Worker 读取表头和概况，核对 Worker 运行核对，取消核对从不打断概况。概况 Worker 按请求的顺序一次只读一个文件，并跳过在等待期间被放弃的读取：在 Chrome 中，一个 Worker 同时读取三个文件流时，其中一个会永远等待。核对会拒绝的文件，在这里就以同样的消息拒绝，因为用的是同一个读取器：格式错误的行、无法解码的字节、超过上限的行数。已有的拒绝提示显示在它下面。被拒绝的文件没有概况。

更改编码会重新读取概况。还在读取中的概况显示目前已读的行数。

选定键列、并且它所在文件的概况已经就绪后，键列会再被读一次，这次更小，称为**键概况**：键为空或只有空白的行数，以及出现在不止一行中的键的个数。它使用评估器自己的 `key` 判断，由核对统计来源键时所用的同一个类计数。

## 核对前的提示

这些事实一旦可知，“你声明的内容”一节就会在“核对之前 · 从文件读取”标题下，说明核对将怎样处理它们。每一行说的是核对将会怎样，从不说使用者应该怎样，也不改变任何选择。

| 事实 | 显示的行 |
| --- | --- |
| 声明的总数与概况的行数不同，并且勾选了完整性声明 | “如果现在核对，目标声明将不被采用：导出文件有 4 行，而不是 5 行。”（来源一侧：“来源声明……文件有……”） |
| 同上，但没有勾选声明 | “如果现在核对，目标总数将被记录为不相符：导出文件有 4 行，而不是 5 行。” |
| 来源键列中有没有键的行 | “如果现在核对，这一批不能是已验证：有 2 行来源在这一列中没有键：`external_id`” |
| 来源键列中有重复的键 | “如果现在核对，这一批不能是已验证：这一列中有 3 个键出现在不止一行来源中：`external_id`” |
| 目标键列中有没有键的行 | “如果现在核对，缺失和唯一性将保持未知：有 1 行目标在这一列中没有键：`external_id`” |
| 目标键列中有重复的键 | “如果现在核对，带有这些键之一的来源记录都不能是已验证：这一列中有 2 个键出现在不止一行目标中：`external_id`” |
| 所选的列不在它的文件中 | “如果现在核对，核对会被拒绝，因为目标导出文件中没有这一列：`hs_email`” |

列名总是放在最后、冒号之后，作为单独的值：它按文件中的写法原样显示，从不翻译，而它前面的句子在英文和中文中意思相同。

每一行都与评估器的做法完全一致。来源总数不一致时，无论是否勾选声明，来源总体都会变成未知；目标总数不一致时，只有勾选了目标声明，目标覆盖才会被撤回，否则只是被记录下来。一条来源记录的键出现在不止一行目标中时，它的唯一性规则不通过；如果它自己的键也重复，则没有任何规则结果：两种情况下它都不是已验证。

提示只在它对当前选择成立时才显示。还什么都不知道、或者没有矛盾时，这一块不出现；它从不说“没有问题”，因为概况不是核对。

0.7.0 在核对之后、在上一次核对没有采用的总数旁边显示的说明保持不变。那些说明读自那次核对的报告；这里的提示读自文件。

## 核对进行时的进度

进度区域显示阶段（读取来源、读取目标、评估记录、生成报告）、两边已读的行数、一个进度条，以及剩余时间的估计。

这个估计如实说明它是什么：“大约还剩 4 秒”，根据目前已读的字节和所用的时间算出。开始的半秒内、或完成不到 2% 时不显示（显示“正在估算剩余时间…”）。显示的值随时钟倒数，只有新估计比它多出四分之一以上、并且多出一秒以上时才向上修正，所以它从不做不必要的回跳。取消会立即结束 Worker。

## 结果浏览

核对结果、已保存的报告以及比较中的任一份报告都使用同一个结果浏览（`ui/src/offline/explore.ts`、`ui/src/components/report/Explorer.tsx`）。它通过一个接口读取记录，这个接口有两种实现：核对 Worker 保留刚写出的报告，在被请求时才构建每条记录；已保存报告的记录本来就在内存中。页面每次只请求一个窗口的行，所以 1,000,000 条记录的结果从不被整个复制到页面中。一项测试要求两者给出相同的答案：对每份核对样例报告和每种筛选，基于核对自身记录的浏览和基于读回的 JSON 报告的浏览列出相同的记录，并且都等于直接阅读报告所得的结果。

结果浏览按报告所记录的样子列出报告。在核对页上，Worker 本可以构建 `details: problems` 报告省略掉的已验证记录的规则结果；它不这样做，因为浏览显示的是报告，而不是比报告更多的东西。

**筛选。** 状态（任何、不是已验证、已验证、不一致、未验证）；规则（`existence`、`uniqueness` 或某个比较字段）和规则结果（通过、失败、未知）；“仅在目标中”把列表切换为范围为 `exact` 的报告中仅在目标中的记录。**搜索**匹配包含所输入文字的键，按原样匹配，区分大小写。**顺序**按行，从前到后或从后到前。列表上方的一行说明有多少条记录符合、共多少条。有不是已验证的记录的结果，打开时显示这些记录；已验证的结果打开时显示全部记录。

**列表**是虚拟化的：每行 40 像素，只有可见的行在文档中。它是一个只有一个 Tab 停留点的列表框：方向键、Page Up、Page Down、Home 和 End 在其中移动，移到的记录即被选中，每个选项都带有它的位置和集合的大小。超过 200,000 行（8,000,000 像素）时，滚动条按比例缩放，让列表的高度保持在浏览器能够排版的范围内。

**面板。** 所选记录在列表旁边打开（手机上在列表下方）：它的行号、键、状态、带有这个键的目标行数，以及每条规则的结果、原因和两边的值。

- 用 `--details problems`（默认）写出的报告，对已验证的记录不保存规则结果。面板如实说明：“这份报告是用 details: problems 写的。它记录了这条记录是已验证，但没有记录它的规则结果和值。”这时规则筛选会说明有多少条已验证记录它无法检验。
- 用 `--redact-values` 写出的报告没有键和值。搜索被关闭，并说明原因。

**地址。** 结果浏览的状态放在地址的 hash 中，这样一个视图可以被链接：`state`（一种状态、`not-verified` 或 `any`）、`rule` 写成规则的位置（`e` 为 existence，`u` 为 uniqueness，`f1` 为第一个字段……）、`result`、表示仅在目标中的 `list`、`sort`，以及表示所选记录的 `row`。只写入与报告打开时的视图不同的部分，所以没有改动过的视图不改变地址。搜索文字从不写入地址，因为它是键的一部分；列名也不写入。在 CSV 核对页上，结果在重新加载后不会保留，所以那里的地址什么也恢复不了；新的核对从它自己的初始视图开始。

每个构建都把标签页图标以 `data:` 地址写进页面，因为地址一变，Chrome 就会再次请求链接的图标，而结果浏览会改变地址。

**内存。** 结果显示期间，核对 Worker 保留上一份报告的评估，以便结果浏览读取：两个 1,000,000 行的文件约 130 MiB，在下一次核对开始时释放。1.0 之前，Worker 在报告写完后就释放一切。

## 字符差异

对于不通过的字段结果，面板显示两个值的不同之处。

- 两个值按码点对齐：共同的前缀和后缀，以及中间部分的最长公共子序列，并使用固定的平局规则。两段中间部分所需的对齐表超过 65,536 格时，整体显示为被替换，面板说明这两个值太长，无法对齐。
- 删除的字符标在来源值上，插入的字符标在目标值上。标记的形式和颜色都不同：删除加删除线，插入加下划线。
- 高亮部分中的、以及值开头和结尾处的不可见字符，画成可见的标记：空格为 `·`，制表符为 `→`，换行为 `↵`，回车为 `␍`；不换行空格、零宽字符和其他格式字符无论在哪里，都画成它们的名称（`NBSP`、`ZWSP`、`ZWNJ`、`ZWJ`、`BOM`、`WJ`、`SHY`），因为它们看起来像什么都没有，或者像空格。其他格式字符、控制字符和空白字符画成码点（`U+202E`）。标记画在虚线框里，不会与文字混淆。
- 其他不同的非 ASCII 字符，在它所在的值下面列出码点（对 `cafe` 后接组合重音的情况，来源下面是 `é U+00E9`，目标下面是 `◌́ U+0301`），这样 Unicode 规范化的差异或形近字母才能被看出来。
- 在浏览器中，满足条件时会加上说明：两个值经 Unicode 规范化（NFC，否则 NFKC）后是相同的文本，或者它们只在大小写上不同。HTML 报告没有这些说明。
- 对于忽略值的一部分的规则（`trim`、`casefold`、`digits`、`date:FORMAT`），面板显示原样的值和比较时所用的值，两者都按报告的记录，并高亮比较时所用的值，因为规则判定不同的是它们。只有不通过的规则会被高亮；结果为未知的规则没有可比较的内容。
- 标记是 `del` 和 `ins` 元素，辅助技术也能说出它们。

它标明：“这里标出两个值的不同之处。上面的规则结果才是结论。”同样的对齐，在 Python 和 TypeScript 中以同样的方式写成，用来画出 HTML 报告中的高亮。

## HTML 报告

独立的 HTML 报告按与应用相同的设计语言重新设计，两种实现写出相同的字节。

1. **结论。** 带有批次结果的印章，声明或“No claim is made: the result is not Verified.”，读到的行数和三项计数，评估时间和评估器。
2. **前提。** 每项前提声明了什么、它的来源、读到的行数，以及声明的总数是否相符；然后用文字说明它是否被采用：“applied”“not applied: the stated total differs from the rows read”“not stated”。以及 FlowAssert 不核实这些声明的那句话。
3. **不是已验证的记录。** 每条一张卡片：行号、键、状态，以及每条规则的结果和原因；对于不通过的字段，显示带字符高亮的两个值，对于做了规范化的规则，还显示比较时所用的值。
4. **仅在目标中的记录**，范围为 `exact` 时。
5. **来源或目标是从哪里读取的**，来自连接器的报告才有，并写明这次读取不能说明什么。
6. **限制**，以及从不评估的四个成员。
7. **输入**：摘要值、编码、核对要求。

它的约束保持不变：没有脚本，没有外部资源，内容安全策略只允许它自己的内联样式，每个值都经过转义。它跟随 `prefers-color-scheme`，可在 A4 和 Letter 纸上打印，记录卡片能放在一页时不会被拆到两页。在手机宽度下没有横向滚动：记录是卡片，而不是宽表格。

字体是读者自己的：页面只列出系统的衬线、无衬线和等宽字体，不嵌入任何字体。

## 测量

两个 1,000,000 行的文件，`FA_LARGE=1 npx playwright test e2e/check-large.spec.ts --project chrome`，在[流式读取说明](1.0-streaming.zh-CN.md#测量)所写的那台机器上，2026 年 11 月 10 日，结果显示之后：

| | |
| --- | --- |
| 列出全部记录（从“不是已验证”切换到“任何状态”） | 0.016 秒 |
| 按 End 跳到最后一条记录，直到它的面板显示 | 0.021 秒 |
| 按规则结果筛选（`field:phone` 失败）：1,000,000 条中有 3 条 | 0.036 秒 |
| 列出、滚动和筛选期间，页面 100 毫秒定时器的最长延迟 | 1 毫秒 |
| 结果显示期间 Worker 保留的堆 | 133 MiB |

在 `details: problems` 报告上做规则筛选时，只有不是已验证的记录会被完整构建；其余 999,997 条没有规则结果，筛选会说明它无法检验它们。
