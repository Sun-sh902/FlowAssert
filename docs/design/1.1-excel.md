## What this adds, and what must not change

Most business exports are `.xlsx` workbooks. From 1.1.0 each side of a check can be one worksheet of a workbook, read
directly, with the same guarantees as a CSV file: read strictly and once, never guessed, refused rather than partly
read, and recorded in the report with a digest.

Nothing that exists changes. Without the new options every command, refusal, summary and report is byte for byte what
1.0.0 gives. A file is read as a workbook only when the person says so: a `.xlsx` file passed to `--source` without
`--source-format xlsx` is still read as CSV, and refused as 1.0.0 refuses it. FlowAssert never chooses the format from a
file's name.

## Options

| Option | Takes | Meaning |
| --- | --- | --- |
| `--source-format FORMAT` | `csv` (the default) or `xlsx` | How `--source` is read |
| `--destination-format FORMAT` | `csv` (the default) or `xlsx` | How `--destination` is read |
| `--source-worksheet NAME` | A worksheet's name, exactly as the workbook spells it | With `--source-format xlsx`: the worksheet to read |
| `--destination-worksheet NAME` | The same | With `--destination-format xlsx` |

Refused combinations, each before any file is read, in this order after the encodings (spec R12.3):

- `--source-format must be one of: csv, xlsx` (and `--destination-format …`);
- `--source-format does not apply to a sheet source` with `--source-sheet`; `--destination-format does not apply to
  a HubSpot destination` with `--destination-hubspot`;
- `--source-worksheet needs --source-format xlsx` (and `--destination-worksheet …`);
- `--source-encoding does not apply to a workbook` with `--source-format xlsx` (and `--destination-encoding …`): the
  parts of a workbook are UTF-8 XML, and FlowAssert reads no other.

`--max-bytes` and `--max-rows` keep their names and defaults, and apply to what is inflated and read, not only to the
file's size ([Refusals and bounds](#refusals-and-bounds)).

The browser chooses the format from the file the person picks, and shows it before the check: a file is read as a
workbook when its name ends in `.xlsx`, `.xlsm`, `.xlsb`, `.xltx` or `.xls`, or its first bytes are a ZIP archive's
(`PK\x03\x04`) or an OLE compound file's, so that a legacy, macro-enabled or protected workbook gets its own refusal
rather than a CSV one; the packaged checker takes `format: "xlsx"` and
`worksheet` on each file; the Action takes the inputs `source-format`, `source-worksheet`, `destination-format` and
`destination-worksheet`.

## Which worksheet

A workbook lists its sheets in `xl/workbook.xml` (`sheets/sheet`, with `name`, `sheetId`, `state` and `r:id`) **[doc]**.
FlowAssert reads every `sheet` element in order, and resolves `r:id` through `xl/_rels/workbook.xml.rels`.

- **With a name** (`--source-worksheet`), the sheet whose `name` equals it exactly, code point for code point. A name
  that matches no sheet is refused with the names the workbook has. A name that names a chart sheet, a dialog sheet or
  a macro sheet (a relationship type other than `…/relationships/worksheet`) is refused: it holds no cells.
- **Without a name**, only when the workbook has exactly one sheet, and it is a worksheet. With two or more sheets,
  hidden ones included, FlowAssert does not choose: a hidden sheet can hold the rows a person means, and the first
  visible one may not. The refusal names every sheet.
- A **hidden** or **very hidden** worksheet is read when it is named. The report records its state.

## From a file to a worksheet

An `.xlsx` workbook is a ZIP archive of XML parts (Office Open XML, ECMA-376 Part 2, Open Packaging Conventions)
**[doc]**. FlowAssert reads it with its own ZIP reader, the same in Python and in TypeScript:

1. **The file's first bytes.** `D0 CF 11 E0 A1 B1 1A E1` is an OLE compound file: a legacy `.xls` workbook and a
   password-protected `.xlsx` workbook are both stored that way (**[unconfirmed]**: no source read says so; FlowAssert
   refuses every OLE compound file the same way, so nothing depends on it), and FlowAssert reads neither. Anything else
   that does not end in a ZIP end-of-central-directory record is not a workbook.
2. **The central directory**, found from the end record in the last 65,557 bytes. It is the authority: every entry's
   name, method, sizes, CRC-32 and offset come from it. An archive that needs ZIP64 (a ZIP64 end record) is refused; a
   ZIP64 extra field on an entry is read. At most 10,000 entries. Two entries whose names are equal ignoring ASCII
   case are refused, because part names in a package are compared that way **[doc]**.
3. **Each part read** is looked up by name, its local header checked against the central directory (name, method),
   and its data inflated as a stream: method 0 (stored) or 8 (deflated), nothing else. The inflated bytes are counted
   as they arrive and must not exceed the remaining byte budget; at the end they must equal the size and the CRC-32
   the directory records. An entry with the encryption flag is refused.
4. **The parts**, in this order: `[Content_Types].xml`; `_rels/.rels`, whose `…/officeDocument` relationship names the
   workbook part; the workbook part, whose content type must be
   `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet.main+xml` (a macro-enabled workbook, a binary
   workbook, a template and a Strict Open XML workbook have other types or relationship names, and are refused); the
   workbook's relationships; `styles.xml` and `sharedStrings.xml` when the workbook has them; then the one worksheet.
   No other part is opened. A relationship with `TargetMode="External"` is refused for every part FlowAssert reads.

In the command line the file is opened once and read with seeks. Its SHA-256 is computed over every byte, in a pass of
its own, before the parts are read; when the parts have been read the file's size and modification time are compared
with those seen at the start, and a file that changed is refused. In the browser a chosen file cannot change, and its
parts are read with `Blob.slice`, in pieces of 1 MiB, inflated by the platform's `DecompressionStream("deflate-raw")`. No part is ever
fetched: the page makes no request.

## The XML FlowAssert reads

The parts are XML 1.0. FlowAssert does not use a general XML parser: Python's and a browser's differ in what they
accept, and a Web Worker has none. It has one tokenizer, written twice, for a subset of XML that every part Excel and
the common writers produce falls within, and refuses everything outside it. In both:

- **Encoding**: UTF-8, with an optional byte order mark. An XML declaration that names another encoding, a UTF-16
  byte order mark, or a byte sequence that is not UTF-8 is refused (`not UTF-8`).
- **A `DOCTYPE`** anywhere is refused, so no entity can be declared and none expanded.
- **References**: the five predefined entities (`&lt;` `&gt;` `&amp;` `&quot;` `&apos;`) and character references
  (`&#N;`, `&#xH;`) to a character XML allows. Any other `&` is not well-formed.
- **Markup**: elements, attributes, character data, `CDATA` sections, comments and processing instructions (the XML
  declaration among them). Names are checked against XML's name characters; an end tag must match its start tag; an
  attribute may not appear twice; text outside the root element may only be white space.
- **Namespaces** are resolved. An element or attribute is known by its namespace and local name, so `<x:c>` in the
  SpreadsheetML namespace is a cell, and an unbound prefix is not well-formed.
- **Normalisation**, as XML 1.0 requires: CR LF and a lone CR become LF in text and attributes, then tab, LF and CR in
  an attribute value become spaces. A character reference is not normalised.
- **Bounds**: a tag (from `<` to `>`) at most 65,536 characters, elements nested at most 64 deep.

A part outside the subset is refused as `not well-formed XML`, with no further detail, so the two implementations
cannot give two different messages for one file. Each problem is met in the order of its position in the inflated
text, whatever the size of the chunks the platform inflates: a byte that is not UTF-8 or a character XML forbids
refuses only after the text before it has been read. The one exception is a deflate stream damaged midway, where
Python's zlib gives none of the failing block's text and a browser may give some; both refuse (spec section 15).

## From a worksheet to rows

A worksheet's cells are the `c` elements inside `sheetData/row` **[doc]**. FlowAssert reads them in document order:

- **Cell references.** A `row` has an optional `r`, its number; a `c` has an optional `r`, such as `B7` **[doc]**. When
  absent, the row is the one after the last, and the cell the one after the last in its row. A reference outside `A1`
  to `XFD1048576`, or not after the last one (rows and cells must increase), is refused.
- **The header is row 1, from column A.** Its last non-empty cell fixes the width; empty cells inside it are columns
  named with the empty string, as `,name` gives in a CSV file. An empty row 1 is refused, with the reason: FlowAssert
  reads the column names from row 1.
- **A data row** is any later row with at least one non-empty cell. A row with none, whether it has no `row` element,
  no cells or only empty ones, is not a record: it is skipped and not counted, as a blank line in a CSV file is.
- **Cells left out** of a data row are empty, as cells left out at the end of a row in a Google Sheets range are.
- **A non-empty cell beyond the header's last column** is refused, as a CSV row wider than its header is.
- **Merged cells.** A merged range stores its value in its first cell; the others are stored empty, though a
  spreadsheet shows the value across the range **[doc]**. FlowAssert reads what is stored, so only the first cell has
  the value, and counts the ranges (`mergeCells/mergeCell`) for the report and the summary.
- **Hidden rows and columns** (`row/@hidden`, `cols/col/@hidden`) are read like any other, including rows a filter has
  hidden. FlowAssert counts them: a person may expect a filtered export to hold only the rows it shows.
- **Every cell of the worksheet** has its text defined below, or the file is refused, including cells of columns the
  check does not compare: the canonical form, its digest and the [records to resend](1.1-exports.md) hold every column.

## The text of a cell

The type is the cell's `t` attribute, `n` when absent **[doc]**. The text is the same in Python and in TypeScript, and
depends on no locale, time zone or program.

| `t` | What is stored **[doc]** | The text FlowAssert reads |
| --- | --- | --- |
| `s` | An index into the shared string table | That item's text: its `t`, or the `t` of each `r` run joined; phonetic runs (`rPh`) are left out. An index that is not a whole number in range is refused |
| `inlineStr` | The string in an `is` element | The same, from `is` |
| `str` | A formula's string result, in `v` | `v` exactly |
| `b` | `0` or `1` in `v` | `FALSE` or `TRUE`, as a spreadsheet's own CSV export writes them **[doc]**. Any other value is refused |
| `n` | A number in `v`, in the lexical form of `xsd:double` | Depends on the number format: [Number formats](#number-formats). No `v` and no formula: an empty cell |
| `d` | An ISO 8601 date or time in `v` | `v` exactly, when it is `YYYY-MM-DD`, optionally followed by `THH:MM`, `:SS`, a fraction and `Z` or `±HH:MM`; otherwise refused |
| `e` | An error, such as `#N/A` or `#DIV/0!` | Refused, with the cell and the error. An error has no text that compares honestly |

Text, in every type:

- **Escapes.** `_xHHHH_`, four hexadecimal digits, stands for that character, and `_x005F_` for an underscore, in
  text a writer could not put in XML otherwise (**[unconfirmed]**, see [Sources](#sources)). FlowAssert decodes them, so a line break Excel stores as
  `_x000D_` is read as a carriage return. An escape that gives half of a surrogate pair is refused.
- **White space** is kept exactly: no trimming, as in a CSV file. XML's own normalisation applies: a line break
  written as CR LF in the part is read as LF; one written `_x000D_` or `&#13;` stays CR.
- **A formula** (`f`) is never evaluated. Its cached value, `v`, is read by the cell's type, as above: the value as the
  file was last saved. A formula with no `v` has no value FlowAssert can read, and is refused.
- **A cell longer than 131,072 characters** is refused, as a CSV field is.

## Number formats

A number cell's style (`s`, an index into `styles.xml`'s `cellXfs`, 0 when absent) names a number format
(`numFmtId`) **[doc]**. The format decides only how a number's text is written, never whether a cell is read:

1. **The format code.** A custom code from `numFmts/numFmt`; else, for the built-in IDs ECMA-376 lists for all
   languages, that code **[doc]**: 0 `General`, 1 `0`, 2 `0.00`, 3 `#,##0`, 4 `#,##0.00`, 9 `0%`, 10 `0.00%`, 11
   `0.00E+00`, 12 `# ?/?`, 13 `# ??/??`, 14 `mm-dd-yy`, 15 `d-mmm-yy`, 16 `d-mmm`, 17 `mmm-yy`, 18 `h:mm AM/PM`, 19
   `h:mm:ss AM/PM`, 20 `h:mm`, 21 `h:mm:ss`, 22 `m/d/yy h:mm`, 37 `#,##0 ;(#,##0)`, 38 `#,##0 ;[Red](#,##0)`, 39
   `#,##0.00;(#,##0.00)`, 40 `#,##0.00;[Red](#,##0.00)`, 45 `mm:ss`, 46 `[h]:mm:ss`, 47 `mmss.0`, 48 `##0.0E+0`, 49 `@`.
   Every other ID depends on the language of the program that wrote it **[doc]**, and one the workbook does not define
   is refused when a number cell uses it.
2. **The section.** A code has up to four sections separated by `;` outside quotes: the first for a positive number,
   the second for a negative one, the third for zero **[doc]**. The section that applies to the value is used: the
   second for a negative value and the third for zero when they exist, the first otherwise.
3. **Cleaning.** Removed from the section: text in double quotes; a character after `\`, `_` or `*`; the word
   `General` in any case; every bracketed token except an elapsed-time one (`[h]`, `[hh]`, `[m]`, `[mm]`, `[s]`, `[ss]`,
   in any case), such as `[Red]`, `[$-409]` or `[>=100]`.
4. **Class.** Lower-cased, the cleaned section is a **duration** if it held an elapsed-time token; otherwise a date or
   a time by its letters: `y`, `d` and `m` as a month are date parts; `h`, `s`, `am/pm`, `a/p` and `m` as minutes are
   time parts. A run of `m` is minutes when the date or time letter before it (skipping other characters) is `h`, or
   the one after it is `s`; otherwise it is a month. `e` is the exponent of a number when `+` or `-` follows it, and a
   date part (an era year) otherwise. A section with no date or time part is a **percentage** when it holds `%`, and a
   **number** otherwise. Any other letter left in the section (`b`, `g`, `n`, …) makes the format one FlowAssert does
   not read, and the cell is refused.

| Class | Text |
| --- | --- |
| Number, percentage, duration | The number, [as written below](#the-text-of-a-number). A percentage is the stored fraction: `0.125` for a cell showing `12.5%`. A duration is the stored number of days: `1.5` for `36:00:00` |
| Date, time, or both | [Dates and times](#dates-and-times) |

### The text of a number

`v` must match `-?(\d+(\.\d*)?|\.\d+)([eE][+-]?\d+)?`; anything else (a `+`, `INF`, `NaN`, white space) is refused. It is
read as the nearest IEEE 754 double, and written as ECMAScript's `Number::toString` writes that double (ECMA-262,
`Number::toString(x)` with radix 10) **[doc]**: the shortest digits that read back as the same double, in plain
notation when the decimal exponent n of the spec is from -5 to 21 (so from `0.000001` up to `100000000000000000000`),
and as `1e+21` or `1.5e-7` outside it, and `-0` as `0`. A value that is not finite is
refused. So `45678`, `0.1`, `13800138000` and `12.5` are read as written, and a stored `1.1000000000000001` as `1.1`.

TypeScript writes it with `String(x)`. Python writes it from `repr(x)`, whose digits are the same shortest digits **[doc]**
, placed by the same rule; a test compares the two on a million random doubles and on every edge of the rule.

## Dates and times

A number cell with a date or time format holds a serial number of days **[doc]**. FlowAssert writes the date it stands
for in ISO 8601, in the workbook's date system, whatever format the sheet displays it in:

- **The date system** is the 1904 system when `workbook.xml`'s `workbookPr` has `date1904` true, the 1900 system
  otherwise **[doc]**. In the 1900 system serial 1 is 1900-01-01 and the year 1900 is treated as a leap year, so serial
  60 is the date February 29, 1900, which does not exist, and serial 61 is 1900-03-01; the upper limit is serial
  2,958,465, 9999-12-31. In the 1904 system serial 0 is 1904-01-01 and the upper limit is 2,957,003 **[doc]**.
- **Milliseconds**: `floor(x × 86,400,000 + 0.5)` in IEEE 754 double arithmetic, the same in both languages; then whole
  days and the milliseconds left.
- **Text**: a time class with zero whole days gives `HH:MM:SS`; a date class with no milliseconds left gives
  `YYYY-MM-DD`; everything else gives `YYYY-MM-DDTHH:MM:SS`. Each adds `.mmm` when the milliseconds are not whole
  seconds. There is no time zone: the workbook stores none.
- **Refused**: a negative serial, serial 60 and serial 0 in the 1900 system (with a date part), and a serial beyond the
  system's upper limit, each with the cell and the serial.

So `45973` formatted `yyyy/m/d`, `mm-dd-yy` or `d-mmm-yy` is read as `2025-11-12` in each case, and `45973.5` formatted
`m/d/yy h:mm` as `2025-11-12T12:00:00`.

## Stored, not displayed

A spreadsheet shows a cell through its format; FlowAssert reads what the file stores. They differ for numbers with a
format (`1,234.50` is read as `1234.5`; `00123` with format `00000` as `123`), percentages, dates, durations and
booleans, and for formulas, whose value is the one last saved. A person comparing with a destination that holds the
displayed text needs to know. So:

- the report counts the data cells of each form (`cells`, below);
- the summary says, for each side read from a workbook, that cells were read as stored values, and how many were not
  plain text ([The printed summary](#the-printed-summary));
- the browser's profile lists the same counts, in words, before the check.

## Refusals and bounds

`FILE` is the path as given (the file's name in the browser), `WS` the worksheet's name and `REF` a cell such as `B7`,
written as Python's `repr` writes a string where shown with quotes. Each message is exact, the same in both
implementations.

| Message | When |
| --- | --- |
| `FILE: not an .xlsx workbook: it is an OLE compound file, the format of legacy .xls workbooks and of password-protected workbooks; save it as an Excel Workbook (.xlsx) without a password` | The first 8 bytes are an OLE compound file's |
| `FILE: not an .xlsx workbook (not a ZIP archive)` | No end-of-central-directory record |
| `FILE: damaged ZIP archive (DETAIL)` | `central directory out of bounds`; `entry header does not match the central directory`; `NAME does not inflate to the data the archive records`, one detail for data that is not deflate, inflates to another size or has another CRC-32, so that no implementation can name a different one of the three |
| `FILE: a ZIP64 archive, which FlowAssert does not read` | A ZIP64 end record |
| `FILE: more than 10000 ZIP entries` | The bound on entries |
| `FILE: repeated ZIP entry NAME` | Two entries with names equal ignoring ASCII case |
| `FILE: encrypted ZIP entry NAME` | The encryption flag |
| `FILE: ZIP entry NAME uses compression method N; only stored and deflated entries are read` | Another method |
| `FILE: inflated parts exceed --max-bytes limit of N` | The bytes inflated so far, or an entry's recorded size, would pass `--max-bytes` |
| `FILE: missing part NAME` | A part the package names is not in the archive |
| `FILE: no workbook part (_rels/.rels names no office document)` | |
| `FILE: a macro-enabled workbook (.xlsm); FlowAssert reads .xlsx workbooks only: save a copy as an Excel Workbook (.xlsx)` | The workbook part's content type is `…macroEnabled.main+xml` |
| `FILE: the workbook part has content type TYPE, not that of an .xlsx workbook` | A binary workbook, a template, or anything else; `none` when the package gives no type |

| `FILE: NAME has a DOCTYPE declaration, which FlowAssert does not read` | |

| `FILE: NAME exceeds a reading bound (a tag longer than 65536 characters, or elements nested deeper than 64)` | |

| `FILE: worksheet WS: row 1 is empty; FlowAssert reads the column names from row 1` | |

| `FILE: worksheet WS: cell reference 'TEXT' is not a cell of a worksheet` | Malformed, or beyond `XFD1048576` |
| `FILE: worksheet WS: cell REF is out of order`, `FILE: worksheet WS: row N is out of order` | A cell or row not after the one before, or a cell not in its row |
| `FILE: worksheet WS: row 'TEXT' is not a row of a worksheet` | A row number that is malformed or beyond 1048576 |
| `FILE: worksheet WS: cell REF has a value beyond the header` | |
| `FILE: worksheet WS: cell REF holds the error value ERROR` | `t="e"` |
| `FILE: worksheet WS: cell REF has a formula without a cached value; open and save the workbook in a spreadsheet program, which stores the values` | |
| `FILE: worksheet WS: cell REF refers to shared string N, which does not exist` | |
| `FILE: worksheet WS: cell REF has no value` | `t="s"`, `str`, `b`, `d` or `e` with no `v` |
| `FILE: worksheet WS: cell REF has the type 'T', which FlowAssert does not read` | |
| `FILE: worksheet WS: cell REF holds 'V', which is not a number` (or `… a boolean`, `… an ISO 8601 date`) | |
| `FILE: worksheet WS: cell REF has style N, which the workbook does not define` | |
| `FILE: worksheet WS: cell REF has number format N, which the workbook does not define` | |
| `FILE: worksheet WS: cell REF has number format 'CODE', which FlowAssert does not read` | |
| `FILE: worksheet WS: cell REF holds the serial number X, which is not a date in the 1900 date system` (or `1904`) | |
| `FILE: worksheet WS: cell REF is longer than 131072 characters` | |
| `FILE: worksheet WS: cell REF holds an escaped character that is not a whole character` | `_xD800_` to `_xDFFF_` |
| `FILE: changed while it was read; run the check again` | Command line: size or modification time changed |
| `FILE: this JavaScript platform has no DecompressionStream, so it cannot read an .xlsx workbook` | Browser and packaged checker only |

**Bounds.** The file's size is checked against `--max-bytes` before it is read, as a CSV file's is. The bytes inflated
from all the parts read, together, may not exceed `--max-bytes` either: an entry's recorded size is checked before it
is inflated, and the bytes are counted while it is inflated, so a ZIP bomb stops at the limit and never fills memory.
`--max-rows` counts data rows. The browser and the packaged checker use the same limits, the page's defaults being the
command line's.

## The canonical form and the two digests

`inputs.source_sha256` (or `destination_sha256`) is the SHA-256 of the canonical form `flowassert-xlsx-csv-1`, which is
the same text as `flowassert-sheet-csv-1` ([Report format](../report-format.md)): UTF-8 without a byte order mark; row
1 as the header, then every data row padded with empty strings to the header's width, each followed by a line feed; a
cell in double quotes, with each `"` doubled, when it contains `,`, `"`, a carriage return or a line feed, or when it is
the only cell of its row and is empty. `flowassert-verify --source` reads that text as exactly the rows the worksheet
gave. `inputs.source_workbook.file_sha256` is the SHA-256 of the file's bytes.

So the two digests answer two questions. The file's digest says which file was read; the canonical digest says which
rows were read, and is equal for two workbooks that hold the same cells, whichever program wrote them. "Identical
content" compares the canonical digests: a workbook and a CSV file holding the same rows are identical content, and are
refused without `--allow-identical-content`, as two such CSV files are.

## The report

A report in which either side was read from a workbook has **`schema_version` 4**, because `inputs.source_sha256` and
`inputs.destination_sha256` then describe a canonical form, not a file, and `source_rows_observed` and the counts'
`observed` describe worksheet rows. Reports of the existing kinds keep their versions and their bytes. Version 4 has
every member of version 1, with the same meaning except for a side read from a workbook; `inputs.source_sheet` and
`inputs.destination_hubspot` keep their version 2 and 3 meanings when present.

`inputs.source_workbook` and `inputs.destination_workbook`, present for each side read from a workbook:

| Member | Meaning |
| --- | --- |
| `format` | Always `xlsx` |
| `worksheet` | The worksheet's name |
| `worksheet_state` | `visible`, `hidden` or `veryHidden` |
| `sheets` | The number of sheets the workbook lists |
| `date_system` | `1900` or `1904` |
| `file_sha256` | SHA-256 of the file's bytes |
| `file_bytes` | The file's size |
| `inflated_bytes` | The bytes inflated from the parts read |
| `columns` | The header's width |
| `rows` | The data rows; equal to `source_rows_observed` for the source |
| `cells` | Data cells by how they were read: `text`, `number`, `percentage`, `date_time`, `duration`, `boolean`, each a count; and `formula`, the cells among them whose value is a formula's cached result |
| `hidden_rows`, `hidden_columns` | Data rows and header columns marked hidden |
| `merged_ranges` | Merged ranges in the worksheet |
| `values` | Always `stored`: cells were read as stored, not as displayed |
| `canonical_form` | Always `flowassert-xlsx-csv-1` |

`inputs.source_encoding` is never present for a workbook side; the other side's encoding is recorded alone when it was
stated. `--redact-values` leaves these members in place: a worksheet's name is not a value. The schema is
`docs/schema/report-v4.schema.json`.

## The printed summary

For each side read from a workbook, after the counts line and the connector lines (spec section 11), in source then
destination order:

```text
Source read from worksheet 'Forms' of an .xlsx workbook: cells as stored, not as displayed.
  Read as stored, where a spreadsheet may display them otherwise: 14 numbers, 2 percentages as fractions, 10 dates or times in ISO 8601, 1 duration in days, 2 booleans as TRUE or FALSE, 2 formula results as last saved.
  Hidden: 2 rows, 1 column, read like any other. Merged ranges: 1, read as stored: only the first cell of each holds the value.
```

The second line appears when any data cell is not text or is a formula's result, listing the non-zero counts in that
order; the third when a data row or header column is hidden or a range is merged, with its non-zero parts. A count of
one uses the singular (`1 number`, `1 percentage as a fraction`, `1 row`). These lines are added for workbooks only: no
line of an existing summary changes, and a count line keeps its words ("file has N rows") for a workbook side too.

## Streaming and memory

| Kept | Why | Bound |
| --- | --- | --- |
| The central directory | To find the parts | 10,000 entries |
| The shared string table, as strings | A cell names an item by index, in any order | Its inflated size, within `--max-bytes` |
| The number formats and cell styles | Small | Within `--max-bytes` |
| One row of cells | Built and handed to the check | The header's width |
| A chunk of compressed data and of inflated text | 64 KiB read at a time | Constant |

The worksheet is never held whole: its inflated text is tokenised as it arrives, and each row is passed to the check as
it ends, exactly as a CSV row is. Beyond what the check itself keeps (the compared columns of the source, as for CSV),
memory grows only with the shared string table. In the browser the shared strings are kept as one string and an array
of offsets, so a million items cost no million objects.

## Why a worksheet and a CSV file give the same result

The check consumes rows: a header and, for each data row, its values. A worksheet gives rows of text exactly as a CSV
file does, and from then on the same code judges them, in both implementations. So the same rows give the same
records, rule results, counts, cohort state and exit status (spec R14.1 already says it for a connector).

"The same rows" means the texts FlowAssert reads, not what a spreadsheet displays: a date is read in ISO form, and a
CSV file exported from the same worksheet may hold `11/12/2025`. Two differences are deliberate: a worksheet row with
no non-empty cell is skipped where a CSV line of empty fields (`,,`) is a row; and a short worksheet row is padded
where a short CSV row is refused. A test runs every golden case whose files a worksheet can express (UTF-8, no row of
only empty fields, no short row) both ways and requires the same records, rule results, counts, cohort state and exit
status.

## Measurements

Filled in from runs on the build machine (Apple silicon, macOS), with the large-file benchmark of 1.0's streaming note.

Each workbook: one worksheet of 1,000,000 data rows and three columns (a shared string key, a shared string, a number
with a format), 22 MB compressed and about 170 MB inflated, with 2,000,003 shared strings.

| Run | Rows | Time to result | Memory |
| --- | --- | --- | --- |
| Command line, two workbooks (Python 3.15) | 1,000,000 each | 19.4 s | 568 MB resident at most |
| Command line, the same rows as two CSV files | 1,000,000 each | 3.4 s | 400 MB resident at most |
| TypeScript reader alone, one workbook (Node 26) | 1,000,000 | 2.8 s | 128 MiB heap after |
| Browser page (Chrome 157), two workbooks, `check-large.spec.ts` | 1,000,000 each | 6.4 s from pressing Check; profiles and key profiles 10.8 s from choosing the files | worker heap 331 MiB at most, 170 MiB held after the check; array buffers 295 MiB at most, 8.7 MiB after a collection; the page's timers at most 2 ms late |
| Browser page, the same rows as two CSV files | 1,000,000 each | 2.4 s | worker heap 192 MiB at most, 133 MiB held |

For the browser run the workbooks have no cell references (`offline/bench/large_xlsx.py`), so they inflate to about
150 MB, within the default `--max-bytes`; with a reference on every cell they inflate past 200 MB and are refused, as
the bound requires. The browser reads a workbook in pieces of 1 MiB with `Blob.slice().arrayBuffer()`, not with
`Blob.stream()`: in Chrome, two streams of one chosen file read at once in a worker (a worksheet's header and its
profile) could leave one of them waiting for ever behind a `DecompressionStream`. Each piece is a new buffer, so the
peak of array buffers counts pieces waiting for the garbage collector; what is kept is small.

The command line is slower with a workbook than with CSV: Python reads the XML with its own tokenizer, written in
Python, where CPython's CSV reader is written in C. A strict fast path takes whole rows and whole shared strings with
one pattern each, and is held to the tokenizer's result by `test_the_fast_path_and_the_tokenizer_read_rows_the_same_way`;
it halved the time. The memory beyond CSV is the shared string table, held for the destination while it is read.
