## Why a node

Since 0.4.0 an n8n user checks with a Code node that holds the packaged checker (`examples/n8n/`): they import a
workflow and edit JavaScript. A community node is found and installed from inside n8n, and set up in a form like n8n's
own nodes. The Code-node example stays, for n8n Cloud, where unverified community nodes cannot be installed **[doc]**.

## Inputs

**Files, as binary properties.** Each input item is one check. The item carries the source and the destination as two
binary properties, by default `source` and `destination` (n8n's "Read/Write Files from Disk", "HTTP Request",
"Google Drive" and "Extract from File"'s neighbours all give files this way). Each is CSV or an `.xlsx` workbook, read
exactly as the command line reads it.

**Items as rows: not in 1.1.** Rule 6 of 1.1 asks that the text of every value be defined exactly. An n8n item's
values are JSON values produced by whichever node came before: a number `1` or `1.0`, a date as a string in that
node's own form, `null`, a nested object. Their text would depend on the node that made them, and the report could not
record a digest of a file, only of FlowAssert's rendering. So the node does not read items as rows; a workflow that has
items converts them with n8n's "Convert to File" node (to CSV), whose bytes the node then checks and records. This can
be added later, as a new input with its own canonical form, if users need it.

## Parameters

Every parameter maps to one option of `flowassert-verify`, with the same default. **Every premise is unstated by
default**, and each premise's description says it is the person's statement, which FlowAssert does not check.

| Parameter | Default | Option |
| --- | --- | --- |
| Source Binary Property | `source` | The binary property holding the source file |
| Source Format | CSV | `--source-format` (`CSV`, `Excel workbook (.xlsx)`) |
| Source Worksheet | empty | `--source-worksheet`; shown for a workbook |
| Source Encoding | UTF-8 | `--source-encoding`; shown for CSV |
| Destination Binary Property, Format, Worksheet, Encoding | the same | The same for the destination |
| Key | required | `--key`: `COLUMN` or `SOURCE:DESTINATION`, in the form's two fields Source Column and Destination Column |
| Fields | one required | A list: Source Column, Destination Column, Rule (`exact`, `trim`, `casefold`, `digits`, `date:FORMAT`) |
| Scope | Source | `scope` (`source`, `exact`) |
| Premise: Source Is the Whole Batch | off | `--source-complete` |
| Premise: Destination Covers the Whole Object | off | `--destination-complete` |
| Premise: Source Total | empty | `--source-count` |
| Premise: Destination Total | empty | `--destination-count` |
| Premise: The Two Files Come From Different Systems | off | `--allow-identical-content` |
| Report Details | Problems | `--details` |
| Leave Values Out of the Reports | off | `--redact-values` |
| Output Records to Resend | on | The records-to-resend outputs; refused with redaction |
| Maximum Bytes, Maximum Rows | 209,715,200, 1,000,000 | `--max-bytes`, `--max-rows` |

Key and fields go into a configuration object, as the browser's do, so the report records `config_file_sha256` and
every rule. The premises' `origin` is `n8n node`, a new value of `origin`, which 1.x may add (compatibility).

## Outputs

Six outputs, in the manner of n8n's own Compare Datasets node, so a workflow branches without an expression:

| Output | Items |
| --- | --- |
| Result | One per input item: `state` (`Verified`, `Mismatch`, `Unverified`, `refused`, `failed`), `exit`, `summary`, `message` (a refusal), `claim`, `counts`, `report` (the JSON report as an object), and the binary properties `report_json` and `report_html`. A refused or failed check has an item too, with no report: a refusal is an answer, not an error |
| Missing From Destination | One item per row of `missing-from-destination.csv` |
| Values Differ | One per row of `values-differ.csv` |
| Duplicated in Destination | One per row of `duplicated-in-destination.csv` |
| Unknown Status (Resending May Duplicate) | One per row of `unknown-status-resending-may-create-duplicates.csv` |
| Only in Destination | One per row of either destination-only file, each with the file's name in `pairedItem` metadata only |

A row item's `json` is the row: each column of its file's header, with its text, and nothing else, so a following
node (a HubSpot or a Google Sheets node) can act on it directly. The Result item also carries each export file as a
binary property (`export_missing_from_destination`, …), byte for byte the command line's. The node fails the execution
only for an internal failure or when "Continue On Fail" is off and the input has no such binary property; a refusal and
every state are results.

## How it checks

The node holds the packaged checker, `flowassert-check.js`, built from `ui/src/offline/` with the browser's check: the
same reader, the same evaluator, the same reports and exports. It calls `checkCsv` with the two files' bytes, the
configuration, the premises and `exports: true`. It makes no network request, reads no environment variable and no
file **[doc: the verification guidelines forbid both]**, and needs no credential. The bytes come from n8n's
`getBinaryDataBuffer`.

## The package

`integrations/n8n-nodes-flowassert/`, named `n8n-nodes-flowassert`, version 1.1.0, MIT **[doc: required for
verification]**. The rest of FlowAssert is Apache-2.0; the owner, who holds the copyright of both, licenses the node
package and the copy of the checker inside it under MIT.

- `package.json`: the keyword `n8n-community-node-package` **[doc]**, the `n8n` attribute naming the node
  (`n8nNodesApiVersion` 1, `nodes`, no `credentials`), `repository.url` exactly the GitHub repository (npm's trusted
  publishing requires it **[doc]**), `files` limited to `dist`.
- **No runtime dependency** **[doc: "verified community nodes aren't allowed to use any run-time dependencies"]**. The
  checker is copied into the package at build time (`scripts/copy-checker.mjs`), with a freshness test that fails when
  it differs from `npm run build:lib`'s output. `n8n-workflow` is a peer dependency, as n8n's own starter declares it;
  it is the n8n instance's, not installed by the package.
- `nodes/FlowAssert/FlowAssert.node.ts`, its codex `FlowAssert.node.json` (`node`, `nodeVersion`, `codexVersion` 1.0,
  `categories` `["Data & Storage"]`, `resources` with links to the README) **[doc]**, and an SVG icon of its own.
- Development dependencies, exact versions at least two weeks old on 2026-11-12: `@n8n/node-cli` 0.55.2 (build and
  lint, which n8n requires for verification **[doc]**), `n8n-workflow` 2.46.2 (types, and the peer the tests load),
  `typescript`.

## Build, lint and test

- `npm run build` is `n8n-node build`; `npm run lint` is `n8n-node lint`, n8n's own rules for community nodes
  (`@n8n/eslint-plugin-community-nodes`) **[doc]**.
- Unit tests (Vitest, in `ui/`'s runner) of the parameters and outputs: every default, every premise off, the mapping
  from parameters to the checker's input, and the six outputs for each state.
- An integration test, `integrations/n8n-nodes-flowassert/test/n8n-run.mjs`: a real n8n started locally with
  `npx n8n@2.47.5` (the latest on 2026-11-12), and again with the installed 2.46.4, each with a temporary user folder
  (`N8N_USER_FOLDER`), the node loaded from the build (`N8N_CUSTOM_EXTENSIONS`), telemetry, version notifications and
  templates off (`N8N_DIAGNOSTICS_ENABLED=false`, `N8N_VERSION_NOTIFICATIONS_ENABLED=false`,
  `N8N_TEMPLATES_ENABLED=false`) **[doc]**, and its own port. It imports a workflow that reads each golden case's files
  and runs the node, then requires the command line's state, exit status, summary and JSON report.

## Publishing and verification

Prepared, not run. `.github/workflows/n8n-node-publish.yml` publishes the package from a tag `n8n-node-v*` with npm's
trusted publishing, so no token is stored: `permissions: id-token: write, contents: read`, a GitHub-hosted runner,
npm 11.5.1 or later and Node 22.14.0 or later **[doc]**, and provenance generated automatically for a public package
from a public repository **[doc]**. n8n requires a node submitted for verification to be published from GitHub
Actions with a provenance statement, from 2026-05-01 **[doc]**. `release.yml` also attaches the package's `npm pack`
tarball with a build provenance attestation.

The owner's steps are in `scripts/dev/n8n_node_publish.md`: an npm account, trusted publishing for the package, the
first publish, installing it in a self-hosted n8n, and applying for verification through the n8n Creator Portal
**[doc]**. Nothing says the node is listed or verified: it is neither.

## What the node does not do

- It does not read Google Sheets or HubSpot: a node that needs no credential and makes no request is simpler to trust,
  and n8n's own nodes already read both; their output, converted to a file, is what the node checks.
- It does not decide what to resend. Its outputs are the records to resend, as advice: a following node acts on them
  only when the person builds it so.
